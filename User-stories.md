

# Введение

Следующие роли: сотрудник, админ, гость.

Гость - пользователь, который имеет доступ только к двум страницам: вход и регистрация.

Сотрудник - пользователь, который может только искать и просматривать информацию. Исключением является изменение данных, носящих чисто информационный характер или являющиеся логином и паролем, своего профиля

Пример названия стандарта: ГОСТ 14771-76.

В качестве синонима слова “стандарт” будет использоваться “ГОСТ”.

# Про нововведения.

Если мной был подчёркнут US, то значительная часть в нём претерпела изменения и его стоит полностью прочитать. В остальных случаях заострять внимания только на отдельные фрагменты.

# 1\. Админ, сотрудник

## 1.1. Переход на главную страницу ("Стандарт") (US-01).

**Действие.** <u>Я кликаю на иконку сайта, на основную ссылку в поисковой системе яндекса или гугла или на кнопку "Стандарты" и перехожу на главную страницу сайта (или соответствующий раздел).</u>

**Результат.** Отображение главной страницы в зависимости от роли.

**Критерии приёмки:**

* система должна уметь распознавать, под какой ролью заходят на сайт;
* отображать главную страницу в соответствии с ролью.
* в шапке есть логотип и кнопки. <u>Для админа отображаются 6 кнопок: стандарты, пользователи, отделы, аналитика, колокольчик (уведомление) и профиль (и так на любой странице для него). Для сотрудника будут только последние 2 и надпись номера отдела, к которому числится. </u>
* в теле хранится окно для поиска и далее ниже таблица ГОСТ-ов.
* окно для поиска содержит по порядку вниз название “Поиск”, поле ввода запроса с его плейсхолдер “ключевое слово, название или наименование стандарта”, checkbox.
* У админа два checkbox: архив, избранные.
* У сотрудника такие же два checkbox из прошлого пункт + “полная база стандартов”, если входит в какой-либо отдел.
* Ниже окна для поиска находится таблица стандартов.
* В элементе списка должны быть такие поля: название стандарта, наименование, сфера деятельности, избранные.
* поле “избранные” содержит checkbox, по которым можно кликнуть.
* ГОСТ-ы в списке отсортированы по убывании дате загрузки в систему.
* <u>должна быть пагинация. Показывать на одной странице до 25 стандартов.</u>
* <u>Должно быть разделение в таблице между строками и столбцами</u>.

## 1.2. Добавление в избранные (US-02).

**Действие.** Я в кликаю по checkbox в поле “Избранные”.

**Результат.** Стандарт(-ы) определяется в группу “избранные”.

**Критерии приёмки:**

* при активации опции (checkbox) “Избранные” в таблице должны отображаться только соответствующие стандарты.
* при клике checkbox должен визуально измениться.
* checkbox кликается только на главной странице и странице просмотра.

## 1.3. Поиск ГОСТ-а (US-03).

**Действие.** Я в поисковую строку ввожу ключевое слово, название или наименование стандарта, применяю по желанию дополнительные настройки (Checkbox)

**Результат.** Вывод списка ГОСТ-ов в соответствии с запросом и заданными дополнительными настройками.

* При запросе по названию стандарта (например, ГОСТ 14771-76) производить поиск по соответствующему критерию. Если это название, то производить по такому же принципу, иначе использовать алгоритмы поиска по ключевому слову.
* checkbox “Архив” отвечает за отображение отменённых стандартов.
* checkbox “Избранные” отвечает за отображение стандартов, которые были отмечены в соответствующем поле таблицы (ГОСТ-ы, которые не были закреплены админом в отдел).
* checkbox “Полный список системы” отображает все стандарты, включая тех, которые не были прикреплены к отделу, к которому числишься.
* checkbox “Статус админа” отображает только админов. ????
* checkbox “отсутствие отдела” отображает только тех пользователей, которые не имеют роль админа и не числятся в каком-либо отделе. ?????
* таблица под действием операции “поиск” должна меняться в соответствии с критериям, упомянутыми выше.

## 1.4. Просмотр информации о ГОСТ-е (US-04).

**Действие.** В списке (таблице) стандартов я кликаю по его названию.

**Результат.** Возможность просмотреть подробную информацию о ГОСТ-е.

**Критерии приёмки:**

* для открытии страницы просмотра ГОСТ-а нужно кликнуть именно по его названию (пример, ГОСТ 890-12).
* чтобы пользователь понял, как перейти на страницу просмотра стандарта, название нужно выделить как ссылку.
* на странице просмотра стандарта должно быть название “Информация о стандарте” и таблица: в первом столбце хранятся поля, а во втором - их значения.
* для админа должны отображаться под таблицей кнопки “изменить” или “удалить”.
* в таблице обязательно должна быть ссылка на сам документ для прочтения.
* должны быть такие поля: название стандарта, наименование стандарта, код ОКС, сфера деятельности, наименование ОКС, содержание (оглавление), статус актуальности, избранные, ссылки, документ, дата загрузки, дата обновления.
* в поле “Ссылки” содержится список <u>гиперссылок</u> на стандарты, упомянутые в данном документе.
* в поле “Дата загрузки” содержится дата загрузки в систему.
* в поле “Дата обновления” содержится дата обновления стандарта в системе.
* в поле “Статус актуальности” содержится информация о действительности стандарта в текущих реалиях. Всего есть 2 значения на выбор: действителен, отменённый. Если статус “отменённый”, то без включения опции “Архив” в таблице отображаться не будет.

**Действие.** Я нажимаю на кнопку “Профиль” или в роли админа кликаю по id в таблице типа “Пользователи”.

**Результат.** Открытие страница “профиль”.

**Критерии приёмки:**

## 1.7. Изменение данных профиля. (US-07).

**Действие.** На странице “профиль” я нажимаю на кнопку “Изменить”. На новой странице я добавляю или меняю данные профиля и затем кликаю по кнопке “Сохранить”.

**Результат.** Открытие страница “профиль”.

**Критерии приёмки:**

* должно быть название “Изменение профиля”.
* на странице редактирования профиля для сотрудника можно поменять фото, фамилию, имя, отчество, логин, пароль.
* для админа добавляются ещё поля: отдел и статус админа.
* после нажатия на кнопку “Сохранить” пользователя нужно перенаправлять на страницу просмотра данного профиля.
* админ не может изменять профиль себе подобного.
* данные должны сохраниться.

## 1.8. Исправление опечатки в поисковой строке. (US-08) [необязательное].

**Действие.** Я ввёл запрос, но система некоторые слова или фразы выделила красным. Кликаю по выделенному фрагменту. Система предлагает верный по её мнению вариант. Я по нему кликаю, после чего фрагмент меняется на предложенный.

**Результат.** Фрагмент, выделенный красной волной снизу, меняется на предложенный системой.

**Критерии приёмки:**

* система фиксирует неверные фрагменты с точки зрения *правил русского языка* и выделяет их красной волнистой линией.
* при клике на выделенный фрагмент всплывает маленькое окно с предложенным вариантом для замены (как google docs).

## 1.9. <u>Просмотр уведомлений (US-09). [Ещё не сделано]</u>

**Действие.** В шапке я кликаю по колокольчику.

**Результат.** Я вижу список уведомлений.

**Критерии приёмки:**

* если появились новые уведомления, у колокольчика должна быть метка их кол-ва.
* новое уведомление должно выделяться особым цветом. Он приобретает стандартный вид после клика.
* всего типа: обновление, изменение, удаление, добавление.
* если админ добавил стандарт, ему придёт уведомление с типом "Добавление".
* если админ удалил стандарт или профиль пользователя, ему придёт уведомление с типом "Удаление".
* если админ изменил стандарт или профиль пользователя или сам сотрудник изменил второе, ему придёт уведомление с типом "Изменение".
* если у пользователя стандарт из избранных или его отдела (если роль сотрудника) обновился, ему придёт уведомление с типом "Обновление".
* при клике по уведомлению "Обновление", "Изменение" или "Добавление" происходит переход на просмотр информации о самом стандарте.
* должен быть фильтр по типу.

## 3.7. <u>Просмотр раздела “Отделы” (US-19).</u>

**Действие.** В шапке сайта я нажимаю на кнопку “Отделы”.

**Результат.** Я перехожу на страницу просмотра отделов.

**Критерии приёмки:**

* должна быть кнопка "Создать отдел".

* элемент имеет такой вид: отдел №### "[Название]". Формат по своему усмотрению можно поменять.

* должно всплыть уведомление о добавлении.

## 3.9. <u>Добавление стандарта в отдел (US-21).</u>

**Действие**. На странице “отделы” я выбираю отдел, который буду пополнять стандартами, и нажимаю на кнопку добавления стандарта. Меня система перенаправляет на страницу “Добавление стандарта в отдел”. Здесь я в таблице избранных стандартов в новом поле “Вкл. в отдел” отмечаю некоторые элементы. В конце, я нажимаю на кнопку “Сохранить”.

**Результат.** Таблица стандартов соответствующего отдела либо полняется, либо убывает.

**Критерии приёмки:**

* Система должна перенаправлять на новую страницу “Добавление стандарта в отдел”.
* в таблице также хранятся избранные.
* Вместо поля “Избранные” появляется поле “Вкл. в отдел”, которое содержит checkbox.
* в окне для поиска остаётся только поисковая строка и кнопка “Сохранить”.

## 3.10. Добавление сотрудника в отдел (US-22).

**Действие**. На странице “отделы” я выбираю отдел, который буду записывать новых людей, и нажимаю на кнопку <u>добавления сотрудника.</u> Система открывает окно, в котором я указываю id пользователя и нажимаю на кнопку “Добавить”.

**Результат.** В отделе изменятся таблица пользователей (полняется или убывает).

**Критерии приёмки:**

* должно появиться именно окно для добавления сотрудника, а не переход на другую страницу.
* в окне вводить именно *id* пользователя.

## 3.11. <u>Переход на страницу аналитики (US-23).</u>

**Действие**.На главной странице в шапке я нажимаю на кнопку “Аналитика”.

**Результат.** Перенаправление на страницу “Аналитика”.

**Критерии приёмки:**

* Главная задача раздела - генерация графиков.
* Должно быть название раздела.
* Будут из группы "Графики" 2 checkbox: "кол-во просмотров" и "кол-во добавлений в избранное".
* Кнопка "Сгенерировать" будет активна, когда будет отмечен один из checkbox.
* Структура у двух графиков одинаковая: по абциссе идут стандарты, а по ординате кол-во просмотров или добавлений.
* Вид диаграмм: столбчатый.
* В качестве параметров фильтрации будут отделы и сферы деятельности.
* Должен быть параметр среза из самых востребованных стандартов и наоборот.
* Кол-во отбираемых стандартов по умолчанию 5. Должна быть настройка, которая позволяла бы увеличивать диапазон среза.
